<what-to-do>

The user has passed (or will pass) a markdown file of raw material.

If the user did not say where to save the article, ask once and remember the path.

Run the beat-by-beat loop:

1. Write 2–3 candidate **starting beats** drawn from the raw material — each a different entry point. Show them before writing anything to the article file. Preview one or two plausible next beats for each, so the user can see a little way down the path. The user picks one.
2. Write **only that beat** to the article file. A beat may be one sentence or several paragraphs — whatever the move naturally requires. Stop there.
3. Re-read the article file from disk. Offer 2–3 candidate **next beats** — different directions from where the article now stands.
4. Loop steps 2–3 until the article reaches a natural end.

</what-to-do>

<supporting-info>

## What is a beat

A beat is one move in the journey. It does one thing — sets a scene, lands a point, asks a question, drops an aside, twists the angle — then stops, leaving the reader at a place where the next beat can pivot.

A beat is sized by what it needs:

- A single sentence if that's all the move is ("And then nothing happened for three weeks.").
- A short paragraph if the move needs setup.
- Multiple paragraphs if the beat is a self-contained vignette, argument, or example.

If a "beat" needs five paragraphs and three subheadings, it's two beats glued together. Split it.

## Writing one beat

Write _that beat only_ to the article file. Do not write ahead.

Pull from the raw material to populate the beat — paraphrase, split, recombine, or quote. The pile is a quarry.

## Ending the journey

The article ends when the journey is complete, not when the pile is empty. Most piles have leftover fragments that don't make it in. That is the point of having more raw material than you need.

## Writing rhythm

- Append one beat at a time.
- Re-read the article file from disk before every write. Preserve user edits absolutely.
- If the user edits a previous beat substantially, let it change what comes next.
- If the user says "rewrite that beat" or "go back and try a different beat 3", do it — edit in place, leave the rest alone.

</supporting-info>
