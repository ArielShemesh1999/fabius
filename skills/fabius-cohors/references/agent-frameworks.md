# Fabius Cohors — the agent-framework & tool-caller map

Loaded on demand by `fabius-cohors`. The skill owns the *definition schema* and the five orchestration patterns; this is the current **best-in-class stack** (2026) to build them on — the frameworks that define/orchestrate agents, the eval that picks the tool-caller, and the open **models** to put behind the action layer. One license law dominates the model half: **a strong open tool-caller's HF tag often lies.** Most (Hermes, Functionary, watt-tool, xLAM-70B) are **Llama fine-tunes** — the *Llama Community License* (attribution "Built with Llama", 700M-MAU clause, no training-other-models) governs the weights regardless of an "Apache/MIT" tag on the repo. For a sellable product, prefer genuinely permissive backbones.

## Harness anatomy — what a complete agent factory assembles

The harness-factory shape above is worth memorizing as a checklist, because the **assembly order is the checklist**: the history provider comes FIRST — every provider registered after it must see the loaded messages — then compaction, todo, mode, and memory, then the opt-in capabilities, then whatever the user adds. Middleware ordering is equally load-bearing and inverts the intuition: **loop middleware sits outermost** (each iteration is a full agent run, approvals included), **tool-approval next** (its re-invocation loop re-runs everything inside it), **message-injection innermost**. Get either ordering wrong and the failure is silent — a provider that never saw history, an injected message the approval loop duplicates.

- **Safe-defaults posture.** Benign capabilities ship on-by-default with a disable flag each; the risky ones — shell, shared file access, background agents, unbounded loops — are strictly opt-in and loudly marked experimental. Copy the posture, not just the feature list.
- **The toolset is composed per run, never static.** Capabilities register their tools per-invocation on the session — which is what lets a mode or a permission change actually change what the model can reach on the next run.
- **Compaction fails silent.** Omitting the token-budget parameters silently disables compaction — declare both the context window and the output ceiling, or state explicitly why compaction is off. An agent that "has compaction" but was never given a budget has nothing.
- **Patterns only** — carry the anatomy, never this framework's API names: several of its surfaces are still experimental, and the checklist transfers to any harness while the names do not.

## Two harness philosophies — fixed-order factory vs plugin service-container

*Harness anatomy* above described one way to build an agent factory: MS Agent Framework's **fixed-order factory** — a known set of capabilities (history → compaction → todo → mode → memory → opt-ins) assembled in one load-bearing sequence, where the assembly order *is* the correctness. There is an opposite philosophy, and choosing between them is a real design decision, not a detail.

- **DeepSeek-harness** (`deepseek-ai/deepseek-harness`, "dsh") · **MIT** · ~139k★ · pushed 2026-08-13 · tagline *"Everything is a Plugin."* — a Node/TS pnpm monorepo (`apps/ packages/ native/ python/`, Vitest/oxlint/tsdown); `npx @deepseek-ai/dsh web` launches a local UI at `127.0.0.1:3080`; plugins carry the `dsh-plugin` tag. It is built on **Cordis**, a service-container / dependency-injection meta-framework with a plugin **lifecycle** and **hot-reload** (Cordis's term: *"spatiotemporal composability"*). *Everything* — models, tools, memory, the UI, adapters — is a plugin over that container. Composition is open-ended and runtime-reconfigurable, not assembled-once.

**The contrast is the choice.** A fixed-order factory buys a *guaranteed* assembly and a checklist you can't get wrong silently — reach for it when the capability set is known and the order is load-bearing (most production agents). A DI service-container buys *swap-at-runtime* — reach for it when the capability set must stay open-ended, when a model or a UI must be hot-swapped without a restart, or when third parties contribute plugins you don't control. The cost is any DI system's cost: the wiring is indirect and "what's actually loaded" is a runtime question, not a read of the assembly code.

**Honest boundary — fabius already lives a form of this.** fabius's own skill/plugin architecture (a router paging specialist layers in on demand) is itself "everything is a plugin," so the *idea* is not the delta. What transfers is narrower and real: the **DI-container + hot-reload lifecycle discipline** as a design reference — a capability *registers → initializes → disposes* against a container and can be replaced live without tearing down its neighbors. Study the lifecycle contract; don't adopt the runtime (a full monorepo + local web UI is the opposite of a lean fabius install).

⚠️ **Version trap.** dsh is a **developer preview** on the `master` branch — DeepSeek states breaking changes are expected, so anything you cite about its plugin API is one force-push from stale. Pin a commit before citing and re-check on bump. `THIRD_PARTY_NOTICES.md` is present — honor it if you ever vendor.

## Crossing an organizational boundary — A2A

The five patterns all assume every worker runs inside a harness *you* own. When the worker is an agent you don't own — another team's, another vendor's — the contract is **A2A**, now **v1.0** under the Linux Foundation (150+ member organizations; shipped inside Azure AI Foundry / Copilot Studio, Bedrock AgentCore Runtime and Google Cloud). Memorize the split, because it settles the routing question outright: **MCP connects an agent to tools and data; A2A connects an agent to another agent across an organizational boundary.**

The wire shape is the cohors contract in someone else's vocabulary, so map onto it rather than inventing a second delegation protocol: an **Agent Card** for discovery (identity, capabilities, skills, service endpoint, auth), a **Task** with an explicit lifecycle (`submitted` → `working` → `input-required` / `completed` / `failed` / `canceled` / `rejected` / `auth-required`), **Messages** for turns and **Artifacts** for results — bound over JSON-RPC, gRPC, or HTTP+JSON/REST.

**A remote agent is still an untrusted worker.** Its Agent Card is a claim, not a credential, and its result crosses a boundary your own reviewer sits behind — validate the return against the output contract *at* that boundary, before it enters the merge (`fabius-praesidium`).

## The deep-research harness — a worked multi-agent shape

When the job is long-horizon research (decompose → gather in parallel → synthesize), don't invent the orchestration cold — there's a canonical worked shape to route against.

- **DeerFlow** (`bytedance/deer-flow`) · **MIT** · ~79k★ · **v2.0.0 cut 25 June 2026**, at the end of a long `v2.0-m*` / `-rc*` tag train — ByteDance's **lead-agent → parallel isolated sub-agents → synthesis** runtime on LangGraph+LangChain, batteries-included: a filesystem abstraction, cross-session memory, a progressively-loaded skill system, sandboxed execution (local/Docker/K8s), MCP tools, and context compaction. The project now bills itself as a **long-horizon "SuperAgent" harness** — sandboxes, memories, tools, skills, subagents, message gateway — not a deep-research pipeline. The reason to keep it: its v1 **coordinator → planner → researcher → reporter** pipeline is the **reference shape** for cohors's *hierarchical + parallel* patterns, and v2's isolated-sub-agent model mirrors the swarm contract (scoped tools + termination per worker). **Adopt as a pattern reference, not a dependency** — it's a full runtime (a large LangChain tree + a Next web UI + IM gateways), the opposite of a lean fabius install. **Version trap, and now it is dated:** anything written before mid-2026 describes v1's narrow deep-research architecture, which remains the reference pipeline but is not what `main` builds today. Pin a version before citing.

## Giving an agent a voice (I/O)

An agent's *voice* is a **modality, not a model**: cohors owns the wiring, `fabius-doctrina` owns the speech model behind it.

- **Voicebox** (`jamiepine/voicebox`) · **MIT** *(app code)* · ~38k★ · v0.5.0 (pre-1.0) — a local-first voice studio (7 TTS engines — Qwen3-TTS, Chatterbox, Kokoro… — plus Whisper dictation and zero-shot cloning) that exposes a **local FastMCP-over-HTTP server**, so any MCP-aware agent (Claude Code, Cursor) gets a chosen **spoken voice** with **no audio leaving the machine**. The clean way to add speech-out to an orchestrated agent — the agent calls a local MCP tool, doctrina's model speaks. **Three caveats fabius prints:** (1) the MIT license covers **Voicebox's code only** — the 7 wrapped model **weights** each carry their own license (several restrict commercial use); verify per-model before shipping. (2) It clones a voice from **seconds of audio with no consent lock** — a biometric-impersonation / deepfake vector: gate it behind consent + provenance (`fabius-praesidium`), and consider sealing/watermarking generated audio (`fabius-catena`). (3) Heavy local install (GPU / Apple-Silicon), young. The **TTS/STT model tier** lives in `fabius-doctrina`.

**Voice in — the polish law.** The other direction has a law of its own: **raw dictation is not the deliverable; the cleaned text is.** The browser's Web Speech API (`SpeechRecognition`, free, on-device, no key) returns an unpunctuated lowercase run-on with every false start and filler still in it — technically the speaker's words, practically not what they meant to type. One **fast-tier pass** between the transcript and the text field is the whole product: punctuate, capitalize, drop the disfluencies and the self-corrections, keep the words. The expensive parts of that pipeline (a model, routing, a key) are already present in any agent worth wiring a mic to — the polish layer is a prompt.

- **The prompt MUST forbid answering.** This is the failure the naive version ships, and it ships every time: hand a model a dictated sentence and it *replies* to it — "what time is the meeting" comes back as an answer about the meeting instead of `What time is the meeting?`. The prompt has to establish that the model is a **transcription editor**, that its entire output is the rewritten text and nothing else, and that a question in the input is **text to punctuate, never a question to answer**. Say it explicitly; the instinct it's overriding is strong.
- **Degrade to the raw transcript on any failure.** Timeout, rate-limit, malformed response, missing key, model outage — the fallback is the unpolished transcript, always. Never an error, never an empty field: **the mic must never lose words.** Polish is an upgrade layered on a path that already works on its own; the moment it becomes a dependency, someone else's 503 eats the user's sentence. (`fabius-disciplina`: the fallback is the thing to prove, since it's the path nobody exercises by hand.)
- **The boundary holds.** cohors owns the **wiring** — when the pass fires, the debounce, the fallback, the never-lose-words guarantee. `fabius-doctrina` owns the **model** that runs it, and the ASR rung underneath it (where Whisper buys punctuation and language auto-detection that Web Speech doesn't, at a metered price — doctrina states that decision rule).

The design inspiration is **Wispr Flow**, which ships exactly this pipeline (speak → clean → paste as if typed). **Stated honestly: it is closed-source and cloud-inference, with no public API to build against — there is nothing here to integrate.** The pattern is what transfers, and the pattern is the cheap half: commodity STT plus a conditioned second pass. No dependency, no license question, no row in `credits/` — an observed product shape, re-derived.

## Evaluating the tool-caller — and, separately, the agent

- **BFCL / Gorilla** (Apache-2.0) — the standard function-calling eval (AST + executable, single/parallel/multi-turn; V4 adds agentic + web-search). Pick the model behind an agent on *evidence*, not vibes; the harness (`bfcl-eval`) reproduces it locally. **Live-updated — re-check the current table; cited scores go stale fast.**
- **τ²-Bench (tau2-bench, Sierra)** (MIT) — the realistic multi-turn *user↔agent* benchmark where **both** call tools (airline/retail/telecom/banking). The companion to BFCL that xLAM/watt-tool cards themselves cite.
- **τ³-Bench (tau3-bench, Sierra)** — the τ line pushed past tool-calling into the two places agents actually break. **τ-Knowledge** scores retrieval over a real internal corpus (a banking domain of ~698 documents across 21 product categories) and is deliberately approach-agnostic — keyword search, embedding retrieval, long context and terminal-style file exploration all compete on the same task. **τ-Voice** scores a live spoken session under accents, background noise and interruption. *Licence is per-release: τ²'s MIT does not automatically carry to the successor — check the τ³ repo.*
- **Terminal-Bench** (`harbor-framework/terminal-bench`, Apache-2.0) — the end-to-end **shell-agent** measurement frontier model cards now report beside SWE-bench: real tasks across software engineering, ML, security, data science and sysadmin (2.0 is 89 tasks; run through the **Harbor** harness).

**Match the instrument to the claim.** BFCL answers *does it emit the right call*. τ² / τ³ answer *does it hold a multi-turn job with a real user, real documents, and a real voice channel*. Terminal-Bench answers *does it finish the work in a shell*. A function-calling score is not an agent score — quoting one for the other is the most common way a model choice gets justified with the wrong number.
