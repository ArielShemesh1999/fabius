# Fabius — routing policy

The decision policy. How fabius chooses a route — which layer / sub-agent, when, and why — and how much machinery to deploy. **Scout wide, strike narrow. YAGNI.**

Loaded on demand by `fabius` (the router). It is small on purpose: every rule here is *operational* — it changes a real decision. Background reading (the papers each rule is drawn from) lives in [`agent-research.md`](agent-research.md) and is pulled only when needed. The lesson log [`failures.md`](failures.md) grows from real incidents, never from anticipation.

> **Honesty.** Each rule names its source. **direct** = the cited agent-research paper makes this claim. **analogy** = the shape is translated from another domain (generative-model sampling math, or a non-agent setting) and the paper does *not* claim it about agents — fabius borrows the shape, not a measured result. Analogy rules carry their caveat inline. Figures (`assets/fig-*.svg`, explained in [RESEARCH.md](../../../RESEARCH.md)) are illustrative shapes, not fabius measurements.

## Decision rules — how to route

### R1 · Classify on three axes before routing
Open every non-trivial task by naming its load on three axes, then route each loaded axis to its layer:
- **Memory** — spans sessions, or a fact/decision worth keeping? → `fabius-archivum`
- **Tools / Action** — needs external state, or a computation the model botches? → `fabius-cohors` (a tool; a *second agent* only when work splits)
- **Planning** — multi-step with dependencies? → `fabius-disciplina`
- **Domain** — does the task sit in a named vertical? → its owner: UI / data-viz / image / diagram → `fabius-decor`; go-to-market → `fabius-mercatus`; defensive security → `fabius-praesidium`; game → `fabius-ludus`; on-chain or provenance-sealing → `fabius-catena`; automation / workflow → `fabius-machina`; science / bio → `fabius-scientia`; model serving / MLOps / LLM-evaluation → `fabius-doctrina`; markets / economy / backtest → `fabius-fortuna`; cross-model council / ensemble deliberation → `fabius-concilium`. Domain picks WHAT; still classify the three process axes above for HOW, and run the vertical as a studio (R13).

Zero axes loaded → stay in the lean `fabius-parcus` core. Publish the classification as the routing rationale.
*Fires: first move on any non-trivial task, before picking a layer or spawning anything.*
*Source: Wang et al., survey of LLM autonomous agents (Profile/Memory/Planning/Action) — **direct**.*

### R2 · Climb the capability ladder one rung; never jump to the top
Add the smallest capability rung the classification demands and stop:
`parcus inline → one tool call → archivum retrieval → disciplina plan → single subagent → cohors swarm`.
Never instantiate rung N+1 until rung N is shown insufficient on **this** task. (Figure: `fig-capability-ladder.svg`.)
*Fires: choosing how much machinery to deploy — especially when tempted to open a swarm.*
*Source: Toward Efficient Agents survey (arXiv 2601.14192) — **direct** on the effectiveness/cost Pareto frontier ("smallest config clearing the bar"); the specific concave shape stays directional, not fitted. Measure real cost per task; defer the swarm gate to cohors's decomposability test, not to cost.*

*Frontier 2026-07 — License a measured exception to "never jump": when the R1 difficulty read is high-confidence (classifier score, prior failure on a sibling task, domain flag), skip rungs directly to the indicated tier — strict smallest-to-largest cascades are provably suboptimal versus cascade routing that skips/reorders per query. Rung-skipping requires a signal, never a vibe. *Source: Dekoninck et al., arXiv:2410.10347 (ICML 2025) — **direct** on LLM cascades, single-turn setting.**

### R3 · Call a tool/sub-agent only when it measurably beats inline
Route to a tool, sub-agent, or specialist only when you can **name the specific wrong answer the call prevents**: stale/external state, a computation you'd get wrong, an independent reviewer who didn't write the artifact, or context past one window. If the model already knows it reliably, answer inline. (Figure: `fig-tool-value-gate.svg`.)
*Fires: any routing decision — tool vs inline, spawn vs do-it-yourself, escalate vs handle in core.*
*Source: Toolformer — **analogy**. Toolformer's loss-reduction filter is computed against the gold continuation at training time, which fabius lacks at routing time. Borrow the spirit (a call must lower expected error), not a runnable metric.*

*Frontier 2026-07 — Measure "beats inline" against the PROMPT-OPTIMIZED single-agent baseline, and default frontier models to the minimal reason-act loop: prompt optimization dominates topology gains (MASS, arXiv:2502.02533 — **direct**); a ~100-line bash-only agent scores >74% SWE-bench Verified (mini-SWE-agent — **direct**); an unscaffolded long-context pass beat tuned scaffolds on the same model, 38% vs 32% (arXiv:2505.08120 — **direct**). Re-ablate any scaffold on every model upgrade — scaffold rankings flip across models (Agentless-era cross-model deltas — secondary reporting, caveat inline).*

### R4 · Scout wide before committing the route
On an ambiguous task, keep **2–3 candidate routes alive** and let cheap scouting evidence average them; collapse to one route only once the signal sharpens. Don't guess the route on turn one.
*Fires: the single correct specialist isn't knowable up front.*
*Source: Flow Matching (marginal velocity = posterior average of conditional velocities) — **analogy**. That identity is sampling math about learned vector fields; the paper never transfers it to route selection. The honest core is fabius's own maxim: scout wide, strike narrow.*

### R5 · Reason → act → observe; never act on an assumed result
In multi-step tool/sub-agent work, gate every action on the **actual observation** before it: one Thought (why this action, what would confirm it) → one Action → read the real result → next Thought. Never stack a second action on an assumed result. After ~3 cycles with no movement toward the verify condition, stop and re-plan.
*Fires: any task interleaving thinking with tool calls / dispatch / lookups where a later step depends on an earlier real result.*
*Source: ReAct — **direct**. This is the per-step gate (catches mid-chain hallucination); `fabius-disciplina`'s prove-before-done is the terminal gate.*

### R6 · Plan in placeholders; bind tool calls only after the plan is fixed
For any task that will call ≥2 tools/agents, finish a **tool-free plan** that names each tool *output* as an abstract placeholder before binding a single call. Then: the skeleton can be grilled up front, independent calls fan out in parallel, and a wrong result invalidates only its placeholder (re-run that one tool, keep the plan). (Figure: `fig-plan-then-bind.svg`.)
*Fires: planning a task that will call ≥2 tools/agents, especially with cross-step dependencies.*
*Source: Chain of Abstraction — **analogy**. The ~1.4× speedup was measured on single-tool math/QA, not multi-agent fan-out. The decoupling is sound; the transferred parallel benefit is unmeasured here.*

*Frontier 2026-08 — Gate the plan before it ships, then keep re-showing it. A half-built plan is a liability, not a head start: an incomplete plan degrades a run FURTHER than handing the agent none, and bolting extra task-relevant phases on early degrades it again when they fight the model's own problem-solving strategy. So a plan that cannot name its **reproduction** step and its **validation** step does not ship — hand over nothing and let the agent work unguided rather than half-guided. A plan in flight also decays: on any run past a handful of steps, re-inject it roughly every **5 steps**, because compliance and resolution both rise when the agent is re-shown the plan and both drift when it is not. This is the concrete mechanism behind R12's stall check — an agent that has drifted off an unrepeated plan looks identical to one that is stuck. (Evaluating Plan Compliance in Autonomous Programming Agents, arXiv:2604.12147 — **direct**: 16,991 SWE-agent trajectories, four models, eight plan variations on SWE-bench Verified + Pro. The direction is measured; the per-model deltas are not in the published text — do not quote numbers for it.)*

### R7 · Branch only when a cheap evaluator can rank unfinished candidates
Spawn a branch-score-prune search (a scored tree) **only when a cheap evaluator can rank half-finished candidates** — a test, a lookahead, a value heuristic, an "is this promising?" vote. Absent that evaluator, no branching factor helps: collapse to a single chain-of-thought / plan pass. The cost of a wrong commit sets only *how wide/deep* to search, not *whether* to branch. (Figure: `fig-branching-accuracy.svg`.)
*Fires: deciding single-path vs branching swarm in planning/brainstorm.*
*Source: Tree of Thoughts — **direct** (Game-of-24: 4%→74% via partial-solution scoring) + RAP (arXiv 2305.14992: LLM-as-world-model + MCTS, reward-ranked partial states). The accuracy-vs-b curve in the figure is a constructed illustration ToT does not publish.*

*Frontier 2026-07 — Three sharpenings: default to the free evaluator — voting is compute-optimal until a generative verifier gets ~8x the compute, and optimal scaling grows solutions faster than verifications (arXiv:2504.01005 — **analogy**, math QA); allocate samples adaptively — commit on inter-sample agreement, spend rollouts only where candidates disagree, saving 33–65% of calls at matched accuracy (TrACE, arXiv:2604.08369 — **direct** on agent step selection, tiny scale: 3B model, n≤50); rank ties toward the SHORTER finished chain and stop the fan-out when the first m finish — shortest chains are up to 34.5% more accurate than longest on the same question (short-m@k, arXiv:2505.17813 — **analogy**, parallel math samples).*

### R8 · Reflect on a verifiable signal, not on vibes; signal type sets the budget
Enter a generate→improve loop **only when an evaluator yields a specific, attributable critique** (cites the exact locus + the fix). Let the signal set the budget:
- **HARD oracle** (test / compiler / linter / schema) → iterate aggressively (cap ~3).
- **SOFT self-critique** → cap at 1–2 passes, and only with a specific cited critique.
- **No critique signal** → ship once, route to human review. Don't manufacture iterations.
(Figure: `fig-reflection-iteration.svg`.)
*Fires: deciding whether a refine loop is justified and how long.*
*Source: Reflexion + Self-Refine — **direct**. Both are agent self-improvement papers; the diminishing-returns shape is their own finding. The caps (~2 soft, ~3 hard) are operational heuristics.*

*Frontier 2026-07 — Add the inverse-scaling cap: on distractor-rich, spurious-cue, or constraint-tracking tasks, SHRINK the reflection budget instead of growing it — accuracy measurably falls with longer reasoning on exactly these shapes — and treat any flip of an already-verified answer as a regression to revert (Gema et al., arXiv:2507.14417; Zhou et al., arXiv:2604.10739 — **analogy**: single-model QA with controlled reasoning length, not agent reflection loops).*
*Frontier 2026-07 — Demote unverifiable signals explicitly: the generator's own grade is not a signal — generation training does not transfer to self-verification (arXiv:2602.07594 — **analogy**); an LLM-judge verdict is tier-3, below executable checks and deterministic diffs — best judges detect research-agent failures at <55% accuracy, weakest on evidence verification (REFLECT, arXiv:2605.19196 — **direct**); when a judge must be used, strip identities, draw judge families disjoint from the actor, run pairwise comparisons in both orders and void order-flipped verdicts — substring matching on agent traces is chance-level (κ=0.049) while a 3-model cross-family ensemble reaches κ=0.432 (AgentProp-Bench, arXiv:2604.16706 — **direct**; order-swap protocol from arXiv:2305.17926 — **analogy**, chat judging).*
*Frontier 2026-08 — Strip the authorship before you spend a soft pass: a model will not correct what it still owns. Re-present the draft, diff, or answer in the next turn as an **external artifact** — a tool result, a memory block, a user-supplied document — never as "critique your previous answer". Byte-identical erroneous content gets flagged tens of points more often once it stops carrying the agent's own voice, and the best role is domain-shaped: a memory block for numeric work, a plain user turn for deductive work. The 1–2 pass cap stands; what changes is that a pass spent on self-labelled output is close to wasted, so re-role first and only then count the pass. Never run the move in reverse — relabelling untrusted INPUT into a trusted role is a measured injection amplifier (one trust-framing line took attack success 3.3% → 70%), so it applies to the agent's own prior output and to nothing else. (The Self-Correction Illusion: Role Relabeling Gates Explicit Error Flagging, arXiv:2606.05976 — **direct**: SHA-256-pinned identical claims across nine models and three domains, +23–93pp on relabeling, significant in 10 of 12 model-domain cells and surviving Holm-Bonferroni in 9.)*

### R9 · Retrieve on demand — read the index, page in only the matching slice
On any `fabius-archivum` read, narrow through the index to the matching slice and load **only those pages**. If the narrowed set still exceeds the context budget, **summarize-then-link** rather than inlining. Never `cat` a whole page or directory "just in case." (Figure: `fig-recall-context.svg`.)
*Fires: any memory read — session start, a query against a growing base, "what did we decide about X" — and the moment you're tempted to cat a `wiki/` dir.*
*Source: MemGPT + agent-memory surveys — **direct**. Read-the-index-first already ships in archivum; the load-bearing addition is the over-budget handler (summarize-then-link).*

*Frontier 2026-07 — Slice size is an accuracy decision, not just cost: models lose 13.9–85% as raw input grows even with provably perfect retrieval, so cut the slice as narrow as the task allows, recite the load-bearing lines before solving (modest ~4% measured gain), and pin paged-in evidence to the context edges adjacent to the question it serves — mid-buffer content is systematically under-weighted, worth up to ~15pp on RAG reading (Du et al., arXiv:2510.05381; Chroma Context Rot 2025; Lost/Found in the Middle, arXiv:2406.16008 — **analogy**: all single-turn QA/RAG, not agent loops).*

*Frontier 2026-08 — "Both edges" is a **text-only** heuristic. Once the buffer carries images — a design review, a screenshot-driven debug, a diagram-grounded question — the U collapses into pure primacy and the tail stops being a safe berth: the same evidence in the first slot beat it in the last by 16–26 points on every reader×benchmark cell, with the bias 2.2–4.5× stronger than the same readers show on text alone. So front-load in mixed-modality contexts and treat the tail as mid-buffer; in text-only contexts the edge rule stands unchanged. (Lost at the End: Primacy Bias in Multimodal RAG QA, arXiv:2606.16494 — **analogy**: measured on three open 7–8B vision-language readers in one fixed prompt layout, and the authors explicitly decline to generalize to larger or proprietary VLMs or to interleaved image placements. Take it as the cheap default when images are in play, not as a law — and re-check it on the model actually running.)*

### R10 · State a constraint once on breadth; hard-steer only narrow contracts
Steering a sub-agent *harder* (repeat / stack / rubric-load a constraint) buys tighter adherence to one axis at the cost of breadth and over-literalness. So on **breadth tasks** (brainstorm, scout, design-explore, fan-out) say it once; reserve hard steering for **narrow contracts** (format, security, output shape). When a route turns rigid, *loosen* the emphasis rather than add more. (Figure: `fig-emphasis-tradeoff.svg`.)
*Fires: tempted to strengthen instruction-following by piling on emphasis — especially after a specialist ignored a constraint once.*
*Source: classifier-free guidance (the w>1 fidelity/diversity trade) — **analogy**. CFG measures image-sampling fidelity vs diversity; "instruction emphasis ≈ guidance weight" is a translation, no agent claim. The verifiable core: emphasis trades breadth for adherence — measure both. Maps to scout-wide (low) / strike-narrow (high).*

## Orchestration & memory rules — how to manage

These extend the routing decision into `fabius-cohors` (orchestration) and `fabius-archivum` (memory).

- **M1 · Spawn a second agent only when it prevents a named error.** Stay single unless work splits into independent parallel pieces, a step needs an independent reviewer who didn't write the artifact, or context exceeds one window. Name the wrong answer the second agent prevents; if you can't, don't spawn. *(cohors · Toolformer-spirit analogy + cohors single-vs-multi gate)*
  - *Frontier 2026-07 — Make the gate two-sided and concrete: positive side, breadth-first independent slices whose value clears a ~15x token multiplier — Anthropic's orchestrator-worker beat single-agent Opus 4 by 90.2% on an internal research eval, token spend explaining 80% of variance, explicitly scoped to parallelizable breadth-first work (**direct**, vendor-reported); negative side, name the prevented error FROM the MAST taxonomy (14 modes, 3 classes, 1600+ traces, κ=0.88 — arXiv:2503.13657 — **direct**), and if the named error is a specification/misalignment mode, fix the single agent's contract (M5) instead — that is the class extra agents create, not prevent.*
- **M2 · Tree vs graph — add a reducer only when partials MERGE.** Combinable sub-results (research synthesis, audit union, sort/merge, dedup) → parallel workers + an explicit reducer/synthesis agent. Competing branches → best-of-k, skip the merge. *(cohors · Graph of Thoughts — analogy; its sorting numbers are intra-LLM, not multi-agent)*
  - *Frontier 2026-07 — Wire multi-agent communication graphs sparse: moderately sparse topologies beat both dense and maximally-pruned ones by suppressing error propagation while preserving signal flow (arXiv:2505.23352, EMNLP 2025 — **direct**); returns to headcount plateau and can invert from coordination overhead alone, even with a single homogeneous model — grow the graph one node at a time against a measured delta (MacNet, arXiv:2406.07155; SIMAS, arXiv:2606.00655 — **direct**).*
- **M3 · Scale verification depth to MEASURED per-route failure.** Set corrector/verify scaffolding from a specialist's measured pass rate — more where it has been failing, none on routes that never fail (drop the corrector, YAGNI). Update the rate from each verified outcome. *(cohors · Consistency-Models / sampling-σ analogy: "an optimal overhead exists only because the model is imperfect")*
  - *Frontier 2026-07 — Audit the meter before trusting the reading: run a null/do-nothing agent through the route (must score ~0), spot-check that tests discriminate, and confirm the parser cannot count empty output as success — unaudited agentic checks mis-estimate performance by up to 100% relative (ABC checklist, arXiv:2507.02825 — **direct** on agentic benchmarks). Then feed the same per-route ledger into ROUTING: adding task-dimension outcome statistics to a vanilla router gave +15.3% relative, and the execution-grounded router got lowest regret and sole OOD robustness (ACRouter, arXiv:2606.22902 — **direct** on coding-agent routing).*
- **M4 · Reflect-then-retry, escalate when hypotheses run out.** On a verifiable failure, write a one-paragraph reflection (what was tried · the failure signal · inferred cause · one changed action) and prepend it to the retry. If a reflection repeats the prior cause with no new hypothesis, stop and escalate to a human (hard cap ~3). *(cohors/disciplina · Reflexion — direct)*
  - *Frontier 2026-07 — Retry by branching, not restarting: checkpoint at verified milestones and decision points, capture the ENVIRONMENT (filesystem/processes/artifacts — chat-only restore recovers correctly in 8% of cases vs 100% environment-aware), and resume from the last good checkpoint — recycling verified prefixes cuts sampling cost up to 17.4% while holding or improving solve rate; add a checkpoint-time structure review, since erosion/verbosity accumulate in ~3/4 of long trajectories and prompting lowers the starting level but not the degradation rate (SWE-Replay, arXiv:2601.22129; Crab, arXiv:2604.28138; SlopCodeBench, arXiv:2603.24755 — all **direct**).*
- **M5 · Specify agents as contracts; accept rewrites only on a metric delta.** Treat any agent/skill prompt as replaceable behind its typed signature + success metric. Accept a prompt rewrite only when a checkable metric on held-out real examples improves — never on better-sounding wording. Prefer bootstrapped demonstrations over long hand-written instructions. *(cohors · DSPy — direct)*
- **M6 · Promote verified solutions to a reusable skill library.** After a self-contained sub-problem is solved **and verified**, promote it to archivum as a named, interface-typed reusable skill; failures leave an anti-pattern note. On every new task, query archivum first and compose existing skills before planning from scratch; supersede, don't duplicate. *(archivum/cohors · Voyager — direct)*
  - *Frontier 2026-07 — Distill trajectories into procedures, not transcripts, and promote in-run: the second use of an agent-written helper in one run is the promotion trigger — runtime tool synthesis+retention alone reached 75.4% SWE-bench Verified / 45.8% Pro (Live-SWE-agent, arXiv:2511.13646 — **direct**); run the library on a correct-and-deprecate regimen, and let the strong tier author procedures the cheap tier consumes — strong-model-built procedural memory measurably improves weaker models (AWM, arXiv:2409.07429: +24.6%/+51.1% relative; Memp, arXiv:2508.06433 — **direct**).*
- **M7 · Page memory explicitly — write only decision-changing facts.** `write = EVICT` (flush durable facts to a page + log line under window pressure / at session end); `read = RECALL` (explicit index→page read on a miss, logged as QUERY). Everything addressable by `[[slug]]`. *(archivum · MemGPT + memory surveys — direct)*
  - *Frontier 2026-07 — Gate every write through an explicit ADD/UPDATE/DELETE/NOOP decision and prefer UPDATE-in-place over near-duplicates — piles of superseded look-alikes suppress retrieval of the current value (PI-LLM, arXiv:2506.08184 — **analogy**, controlled probes); persist a lesson only after its outcome verified, and use later task results as free quality labels — mark or delete records implicated in failed runs in the same session (arXiv:2505.16067; Memory-R1, arXiv:2508.19828 — **direct** on LLM-agent memory).*
- **M8 · Rank ties by recency and load-bearingness; synthesize grown logs.** When many index entries tie on relevance, break the tie by `updated` date and how load-bearing the page is. Fold a grown batch of un-synthesized log lines up into a synthesis page — no numeric importance tag, no threshold counter. *(archivum · Generative Agents — analogy: proposed for a simulated observation stream, not a curated wiki; fabius drops the numeric machinery)*
  - *Frontier 2026-07 — Add idle-time consolidation with a predictability precondition: pre-digest a stable context (decisions, invariants, open threads) at session close only when future queries about it are foreseeable — measured ~5x test-time-compute reduction and 2.5x amortized cost, collapsing when queries are unpredictable (Sleep-time Compute, arXiv:2504.13171 — **analogy**, stateful math QA); and prune/re-synthesize the store itself as it grows — best-in-class filtered memory dropped ~25% when the store grew 10x (Mem0 BEAM 2026 — **direct** setting, vendor-reported, not peer-reviewed).*

## Capability-tier, long-horizon & vertical rules

These extend R1–R10 / M1–M8 with the dispatch dimensions the praetorium adds — which model tier to spend, how to run a long-horizon loop, how a vertical composes, and how the system packages its own corpus. Same honesty discipline: **direct** = the source claims it; **analogy** = the shape is borrowed, the caveat is inline.

> **Inside the proven core.** All four carry full formal proofs — R11 as an index-policy theorem (ρ=c/p cascade, R3's gate over tiers), R12 as optimal stopping with a dual exit gate and a.s. termination, R13 as a conflict-freedom/termination/goal-preservation composition theorem, M9 as a lossless-paging dominance bound with an explicit recall threshold — each adversarially verified twice, and the coherence theorem in [RESEARCH.md](../../../RESEARCH.md) is established over the full **22-rule set** (verdict: *coheres, with exceptions printed in full* — whitepaper §5). The working edge is the **frontier layer** below (R14–R16 · M10–M13), which stays outside the theorem by construction until its own proofs are paid.

### R11 · Spend the cheapest model tier that holds; escalate on a miss, not a guess
Route each sub-task to the lowest-capability, lowest-cost model that clears its bar, and re-tier **per sub-task**, not per session. Reserve the strong tier for ambiguity, architecture, security calls, and irreversible actions; hand mechanical, tightly-contracted work (format, transform, lookup) to a cheap tier. Escalate a tier only on a **verifiable** miss (R8), never on a hunch.
*Fires: any dispatch where work splits into sub-tasks of differing difficulty — and whenever tempted to run everything on the top model.*
*Source: Toward Efficient Agents survey (arXiv 2601.14192: rewards that minimize tool invocation, the cost-effectiveness frontier) — **direct** on the principle; FrugalGPT-style cascades for the escalate-on-miss mechanism. The specific savings are task- and dataset-specific; the cost figure does not transfer.*

*Frontier 2026-07 — Route pre-generation when a difficulty signal already exists: a try-then-escalate cascade always pays the cheap attempt before deciding, and that structural sunk cost dominates the frontier — a lightweight pre-generation router beat the best cascade on 4/5 benchmarks (Bouchard, arXiv:2605.06350 — **direct** on LLM cascades, single-turn; theoretical support Mahmood, arXiv:2602.09902 — proofs only). Reserve generate-then-escalate for when no pre-signal exists or the cheap draft is reusable by the stronger tier.*
*Frontier 2026-07 — The ladder gains intermediate rungs, tried in order: (1) best-of-n at the cheap tier when a cheap ranker exists — up to 60% cost cut at <1% quality drop, sometimes exceeding the strong model (BEST-Route, arXiv:2506.22716, ICML 2025 — **direct**; note its selection is pre-generation); (2) cheap generator + verification pass — the Gemma2 9B→27B gap shrank 75.7% post-verification, but no verifier lets a weak model exceed the strong one's single shot (arXiv:2509.17995 — **analogy**); (3) one same-tier thinking-effort step, only for reasoning-shaped misses — never default high: across 21,730 agent rollouts higher effort reduced accuracy in the majority of runs (HAL, arXiv:2510.11977 — **direct**), and more thinking does not fix knowledge-shaped misses, it raises hallucination — those route to retrieval/tools or the next tier (arXiv:2509.06861 — **analogy**).*

### R12 · Long-horizon work runs `step → verify` on a loop with a dual exit gate
For multi-cycle autonomous work, repeat the `fabius-disciplina` `step → verify` cycle and stop only when **both** a completion condition **and** an explicit done-signal hold. Hard-cap the cycles; on a stuck loop (no movement toward the verify condition across ~3 cycles, or a reflection that repeats the prior cause with no new hypothesis) stop and escalate — never spin. Rate-limit and checkpoint so a runaway can neither burn unbounded cost nor corrupt state.
*Fires: a task needing many autonomous iterations — a large migration, a codebase sweep, an unattended build-until-done.*
*Source: the Ralph autonomous-loop technique (Huntley) + the Reflexion stop-condition (M4) — **direct** on the loop-plus-gate shape; the specific caps are operational heuristics. The gate is what separates "autonomous" from "infinite".*

*Frontier 2026-07 — Size each autonomous segment well inside the model's measured 50% time horizon (METR TH1.1: ~131-day doubling post-2023; longest measured frontier horizon ~14.5h, unreliable above ~16h — re-look up per model generation): success decays roughly exponentially with duration under a near-constant per-minute hazard, and Verified-level scores collapse below 25% on hours-to-days enterprise tasks (METR arXiv:2503.14499; Ord arXiv:2505.05115 — author's own generalization caveat; SWE-Bench Pro arXiv:2509.16941 — all **direct**). Inside the loop, tier per STEP: run cheap by default with stuck/milestone monitors, escalate only the firing step, then drop back down (arXiv:2604.27151 — **direct** mechanism on computer-use agents; headline efficiency numbers unverified).*
*Frontier 2026-07 — The gate must co-evolve: every verifier is a proxy for intent, and as a route's pass rate climbs toward the gate's ceiling the GATE becomes the stale component — the agent starts satisfying the check instead of the task. Tighten it (more tests, sharper rubric items, a live/human check) before trusting a long green streak, and revise the gate on every generator upgrade (The Verification Horizon, arXiv:2606.26300 — **direct** for coding agents; caveat: partly internal-benchmark and position-style evidence).*

### R13 · A vertical runs a studio — the domain skill leads a mini-pipeline
A domain task that needs more than one layer (a game, a launch, a security review, a landing page) composes as a pipeline behind one goal: the **domain skill leads** (sets the WHAT and the domain laws) → `fabius-disciplina` plans and proves → the execution layers (`fabius-decor` / `fabius-cohors`) follow → `fabius-parcus` underneath. Don't collapse a vertical to a single layer, and don't let a downstream layer redefine the domain goal.
*Fires: any task spanning a domain + execution + process — i.e. most real deliverables, not a one-line edit.*
*Source: fabius's own composition rule (process picks HOW, domain picks WHAT), generalized from the landing-page path — **direct** (the system's own single-owner discipline applied to multi-layer jobs). No external claim borrowed.*

### M9 · Externalize the corpus — the brain holds the index, not the library
Bulk reference material (agent catalogs, design teardowns, swipe files, hardening guides, vector stores) **belongs outside** the installed plugin as an indexed corpus. Each skill ships a lean entry doc + an index and pages in only the matching slice on demand (R9 · M7). Never bundle a *new* library into the artifact: it bloats the install, contradicts the lean stance the benchmark proves, and gives the model nothing a 50-line catalog wouldn't. **Adding a capability = adding an index entry, not a megabyte.** (Honest current state: full libraries still ship bundled under `references/` and are migrating behind the index — which ones, and the count, are tracked in [CORPUS.md](../../../CORPUS.md), the single owner of that inventory.)
*Fires: packaging the system; any time a `references/` folder grows past a lean entry doc.*
*Source: MemGPT paging (R9 · M7) + the Memory-for-Agents survey (arXiv 2603.07670: context-resident compression, retrieval-augmented stores, write-path filtering) applied to the system's own packaging — **direct** on read-the-index-first. The standing rule behind the corpus split (see ARCHITECTURE extension points).*

## The frontier layer — R14–R16 · M10–M13 (researched 2026-07)

Distilled from a deep-research pass over the 2025–26 agent-research frontier (eight topic sweeps, every finding honesty-audited before admission; the full source notes live in [agent-research.md](agent-research.md)). Same discipline as everything above: **direct** = the source measured the claim on LLM agents or routing itself; **analogy** = the shape is borrowed, the caveat is inline. Two of these rules (M11, M12) formalize what fabius's own Run 7 (FBS v1.0) measured in-house — the benchmark feeding the brain.

### R14 · In a tool loop, act for feedback before reasoning past it
Cap per-step deliberation inside an agentic loop: the moment a thought starts simulating what a tool call would return, or chains predicted outcomes more than one step deep without touching the environment, stop and make the cheap call — real feedback beats imagined feedback. Treat the three measured overthinking patterns (analysis paralysis, rogue multi-action batches, premature disengagement) as signals to LOWER reasoning effort, not raise it. When candidate trajectories tie, prefer the one that interacted more and deliberated less: two low-effort runs with the less-overthinking one selected nearly matched one high-effort run at 43% less compute. This is R5's converse — R5 forbids acting on an assumed result; R14 forbids refusing to act while assuming results anyway.
*Fires: every agentic step where a reasoning segment exceeds roughly one screen without an intervening tool call; when ranking candidate trajectories; whenever a retry inside a tool loop is about to raise reasoning effort.*
*Source: Cuadron et al., arXiv:2502.08235 (4,018 SWE-bench Verified trajectories: overthinking score predicts failure; k=2 low-effort + low-overthinking selection → 27.3% success at 43% less compute) — **direct**: measured on LLM coding agents in real tool loops. Corroborated by HAL (arXiv:2510.11977, 21,730 rollouts: higher reasoning effort reduced accuracy in the majority of runs) — **direct**.*

### R15 · Audit the oracle before trusting green
When a route's exit gate is an existing check (test suite, validator, judge), grade the gate before treating a pass as done: confirm the changed lines are actually exercised and add at least one assertion targeting the exact behavior the work claims to deliver — roughly one in five agent patches that pass weak suites is semantically wrong. Treat "all tests pass" on an unaudited suite as PLAUSIBLE, never CONFIRMED: a green from a strengthened gate ends the route, a green from a weak one only ends the step. The same logic caps retries — with any nonzero false-positive rate in the gate, a resample loop saturates at a hard ceiling (optimal sample counts are often under 10), so when a gated loop keeps failing, improve the CHECK or escalate the generator, never just raise N.
*Fires: any route whose completion condition is "tests pass" or "the checker accepted", especially inherited, sparse, or legacy suites; any best-of-N / retry-until-green loop gated by a check known to pass wrong answers.*
*Source: SWE-ABS (arXiv:2603.00520) — **direct**: strengthening the suites of 251/500 SWE-bench Verified instances rejected 19.7% of the top-30 agents' previously passing patches (top score 78.80%→62.20%). Retry ceiling: The Limits of Inference Scaling Through Resampling (arXiv:2411.17501) — **analogy**: measured on code generation under limited-coverage unit tests, not full agent trajectories; the <10 optimum is benchmark-specific, the ceiling argument general.*

### R16 · Bind test-first to the impact map, not to a slogan
Before patching, page in the tests that actually cover the touched code (a source→covering-tests impact map), confirm or write a failing reproduction test, and gate the patch on that targeted set plus the mapped regression set. Never inject generic "write tests first" boilerplate without the concrete test context — untargeted TDD prompting measurably INCREASED regressions beyond doing nothing (9.94% vs 6.08% baseline; the mapped version cut them to 1.82%). Spend surplus budget on authoring and validating the reproduction test, not on more patch attempts: with a trustworthy failing test in hand, resolution is the easy half (94.3% on SWE-bench Verified when ground-truth tests define the target).
*Fires: bug fixes and feature patches in any repo with an existing suite; any prompt template about to include TDD boilerplate; the test-first step of every disciplina coding route.*
*Source: TDAD (arXiv:2603.17973) — **direct**: dependency-mapped test context cut regressions 70% and lifted resolution on SWE-bench Verified with open-weight models, while slogan-level TDD prompting was actively harmful. TDFlow (arXiv:2510.23761) — **direct**: 94.3% Verified under a narrow test-driven workflow once tests exist; the measured bottleneck is reproduction-test authorship.*

- **M10 · Sample the best model before convening a council; cap debate at one verified round.** Before any multi-model council or MoA-style aggregation, run N samples of the single strongest available model and reduce by vote or judge — route to a heterogeneous council only when those samples fail the SAME way (correlated error), not when they merely disagree. Never add a weaker model for "diversity" and never mix capability tiers in a debate pool: debate accuracy measurably decays over rounds as models flip correct→incorrect under peer pressure, and base-model strength — not debate structure — is what drives the outcome. Allow a second debate round only if a verifiable signal improved after round one, and tune N per task: vote aggregation is non-monotone in call count, so more samples on a hard-query mix can lower accuracy.
*Fires: "ask several models", concilium routing, any debate loop, MoA-style aggregation, sample-and-vote budget choices.*
*Source: Self-MoA (arXiv:2502.00674) — **direct**: ensembling the single best model beat mixed-model MoA (+6.6 AlpacaEval 2.0, +3.8 avg); Talk Isn't Always Cheap (arXiv:2509.05396) — **direct** on LLM debate, caveat: workshop paper; Are More LLM Calls All You Need? (arXiv:2403.02419) — **direct**: Vote/Filter-Vote non-monotone in call count; Can LLM Agents Really Debate? (arXiv:2511.07784) — **direct**, caveat: single logic-puzzle domain. All measured on LLM ensembles/QA, not tool-using fleets — work-splitting stays M1/M2 territory.*

- **M11 · Gate prose deliverables on a failure-taxonomy rubric — and check the artifact IS the deliverable.** When a route's output has no executable check (research reports, plans, analyses, long-form deliverables), never gate it with a bare "is this good?" judge call: build the rubric from that route's known failure modes (missed sub-questions, unsupported claims, wrong scope, stale sources) and verify item-by-item, feeding failed items back for one refinement pass. The rubric's first item is existence — the artifact must CONTAIN the deliverable, not refer to it: Run 7's FAB-025 measured a mid-tier model under the lean stance shipping a 363-char stub that pointed at a plan it never wrote (1.5/28 vs 28/28 for baseline). Structured rubric verification beat vanilla agent-as-judge by 12–48% meta-eval F1 and added 8–11% end-to-end accuracy as a test-time gate on deep-research benchmarks.
*Fires: exit gate of any route whose deliverable is prose/analysis rather than a checkable artifact; whenever an LLM-judge gate is about to ship with a one-line prompt; every LONG deliverable produced under a compression-biased stance.*
*Source: DeepVerifier (arXiv:2601.15808) — **direct**: measured on deep research agents (GAIA, XBench-DeepSearch hard subsets); gains reported with capable closed-source verifier models, so budget a capable model for the gate. The stub-collapse clause is Run 7 (FBS v1.0, 2026-07-05) — **direct**, in-house measurement.*

- **M12 · Treat retrieved memory as a suspect witness — and stand it down on fresh-eyes routes.** A retrieved record is a candidate, not context: before injecting it, check that the current task actually matches the record's situation (not just its wording) and that its outcome was verified when written — agents imitate what they retrieve, errors included. Inject the one or two records that pass and discard the rest; when candidates conflict, keep only the most recent verified value. Dampen or disable recall on security, incident, and error-recovery routes — Run 7 measured recall lifting design/product +4.91/28 while COSTING security −1.57 and error-recovery −1.37, because recalled context distracts fresh-eyes rigor — and skip injection entirely below a complexity floor, where memory is measured pure overhead.
*Fires: between every archivum/vault retrieval and the prompt that uses it; at task intake, where a trivial (R1) or security/incident classification sets the recall dial down or off.*
*Source: experience-following (arXiv:2505.16067) — **direct**: LLM agents copy retrieved records including their errors; Memory-R1 (arXiv:2508.19828) — **direct**: filtering retrieved candidates before answering beats passing them wholesale; the security/error-recovery dampening is Run 7 (FBS v1.0) — **direct**, in-house; the trivial-task floor is the Stompy coding-agent pilot (2026) — **direct** setting but pilot-grade (n=9, no statistical significance).*

- **M13 · Compact by masking first, below the advertised window — summarize only what masking loses.** Set an explicit resident-token budget well under the documented context limit at loop setup, and compact the moment the transcript crosses it: the measured failure mode is silent accuracy rot long before overflow. The first rung is mechanical — replace stale tool OBSERVATIONS with one-line placeholders while keeping the reasoning-action spine verbatim; climb to LLM summarization only for masked spans that provably held decision-changing facts, and summarize that span, not the whole log. On software agents, masking matched or slightly beat paid summarization at roughly half the cost of raw retention; on an enterprise tool-agent benchmark, pruning to the last 5 tool exchanges beat full retention outright (79% vs 71%), with prune+summarize best (91.6%).
*Fires: at loop setup (set the budget) and at every turn the transcript crosses it; any impulse to "summarize the whole conversation"; long tool outputs (logs, diffs, page dumps) more than a few turns old.*
*Source: The Complexity Trap (arXiv:2508.21433, SWE-bench Verified, 5 model configs) and Less Context, Better Agents (arXiv:2606.10209, 50 enterprise tool tasks) — **direct**: both measured on tool-using LLM agents, software/enterprise domains only. The compact-below-the-limit trigger transfers from single-turn measurements (Chroma Context Rot 2025; Du et al., arXiv:2510.05381) — **analogy**: no public per-model threshold table exists, so calibrate the budget on the actual model, never the spec sheet.*
  - *Frontier 2026-08 — Do not hand-roll compaction on a runtime that ships it. Where the platform exposes context management as an API surface, **declare** the budget there instead of reimplementing masking in the harness: on Anthropic's, this rule's first rung is a configured strategy, not code you write (`clear_tool_uses_20250919` — placeholder-replaces old tool results, default trigger 100K input tokens, keep the 3 most recent, with `clear_at_least` / `exclude_tools` / `clear_tool_inputs` knobs; `clear_thinking_20251015` for thinking blocks), and server-side compaction is its own strategy (`compact_20260112`, beta header `compact-2026-01-12`, default threshold 150K input tokens, floor 50K). Note the vendor's order **inverts** this rule's default — compaction is recommended as the primary strategy with tool-result clearing kept for fine-grained control — so pick deliberately against your own measurement, not by habit. Two hard consequences: client-side `compaction_control` is deprecated in the Python, TypeScript and Ruby SDKs and must not be built on; and every shipped default sits far above where accuracy starts rotting on a long tool loop, so the threshold is a parameter you tune DOWN, never one you accept. The masking-vs-summarizing tradeoff above still governs WHICH strategy you declare; it no longer governs whether you write the plumbing. (Anthropic context-editing + compaction docs, 2026-08 — **direct** vendor contract, one provider only: on a runtime with no such surface, M13's ladder is still yours to build by hand.)*
