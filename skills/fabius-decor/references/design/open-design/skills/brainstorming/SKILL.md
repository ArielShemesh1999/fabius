# brainstorming

## What it does

Converts vague input into concrete design directions by asking the right questions, surfacing constraints, and generating distinct alternatives. Use early in concept work before committing to a direction.

## When to use

- The design brief is underspecified or contradictory.
- Multiple valid directions exist and a choice is needed before building.
- The user wants to stress-test an idea before investing time.

## Steps

1. **Extract the core intent** — ask one clarifying question if the goal is ambiguous. Avoid asking more than two.
2. **Map constraints** — list known constraints (platform, audience, time, brand, tech stack).
3. **Generate 3 distinct directions** — each must differ meaningfully in layout, tone, or interaction model. No two directions should be variations of the same idea.
4. **Annotate trade-offs** — for each direction, state what it optimises for and what it sacrifices.
5. **Recommend one** — pick the strongest direction and state why, then hand off to the user for a decision.

## Output

A short written brief: constraints list, 3 named directions with trade-offs, and a recommendation with rationale. Ready to feed into the next design or build step.
