### Copyleft & fair-code note (integrated toolkits)

**Four** classes of not-plainly-permissive terms appear above, and fabius flags each where it appears: **OpenMontage** and **open·kritt** are **AGPL-3.0** (network copyleft — open·kritt specifically **AGPL-3.0-only**), **Open WebUI** carries a **branding-protection clause** (no white-labeling above 50 users without an enterprise license), **Flowise** is **open-core** (Apache-2.0 community core + a proprietary Commercial enterprise partition), and **GitNexus** is **PolyForm Noncommercial 1.0.0** — a **fourth class**, and the strictest of the four for this repo. As with every other row here, fabius **re-expresses the pattern in its own words and bundles no upstream files** — so none of these terms are triggered by the fabius install today. If any such file is ever vendored into the corpus, its `LICENSE` travels with it and the constraint is honored in full: the AGPL's source-offer obligation, Open WebUI's branding lock, and Flowise's enterprise boundary each stand. To state the open·kritt case plainly: it is **AGPL-3.0-only network copyleft** — fabius re-expresses its patterns and bundles nothing, so the copyleft is never triggered; and its `CONTRIBUTION_TERMS` additionally **assign contributor copyright to the project's owners**, one more reason nothing is ever upstreamed.

**PolyForm Noncommercial is different in kind, not just in strictness — state it plainly.** It is *fair-code, not open source*: the grant covers **noncommercial purposes only**. For a proprietary product fabius is sold as, that makes GitNexus's source **legally untouchable at any volume** — no vendoring, no copying, no adaptation, and no "vendor it and carry the LICENSE" escape hatch, because there is no volume of attribution that turns a noncommercial grant into a commercial one. The other three classes constrain *how* you may ship the code; this one removes shipping it as an option. What fabius took is the **structure of an idea expressed in markdown prompts** — thin ground where idea and expression nearly meet, which is exactly why the line was drawn hard: re-authored end to end in fabius's own words, no code, no persona text, no wording carried.

It also carries a **supply-chain trap** worth naming once, because it is the reason a careful team ships this license by accident: **GitHub reports PolyForm as `NOASSERTION`**. A dependency gate written the obvious way — block AGPL, allow the rest — passes a noncommercial license straight through and reports green. `fabius-praesidium` owns that as a default-deny finding (`hardening-guides.md` §9: an unidentifiable license is an unmeetable one), alongside treating any copyleft/branding/gated dependency in a shipped product as a licensing risk to surface.

**A second worked instance now lives in the references.** `watermarks-remover` is **MIT** at its core, but its advertised watermark-removal capability reaches for optional external backends under worse terms — **reverse-SynthID (Non-commercial Research License)** and **noai-watermark (no license = all-rights-reserved, reported by GitHub as `NOASSERTION`)** — the same §9 trap in a second tool: a core you may ship gated behind a backend you may not. fabius bundles and depends on none of them; it is cited as an audit example (`skills/fabius-praesidium/references/supply-chain-and-ai-artifacts.md` §7), not a fabius licensing exposure. The "Four classes" count above is unchanged — those are adapted-from sources; this is a referenced specimen (the pattern fabius adopts here is the MIT invisible-char strip and metadata split; the ⚠️ backends contribute no pattern, only the cautionary tale).

## Upstream registry

[`upstream.json`](upstream.json) (`fabius-upstream/v1`) is the machine-readable side of this file: one entry per registered upstream with its repo URL, owner, SPDX license, how it is consumed (`informed-by` or `bundled`), the owning fabius layer, the repo-relative paths it touches, and the upstream commit and version a reference was written against. It seeds with the eleven bundled sources (sixteen license-scoped trees; legacy — no pin recorded) and the three references studied in the 2.7.0 pass (pinned to a full commit SHA); the older informed-by rows above are not registered yet. `sync` is `manual` on every entry: nothing fetches, nothing updates itself. `node scripts/verify-upstream.mjs` — a gate in `scripts/verify-all.sh`, so CI runs it — checks the registry against the working tree offline: field shapes and the license allowlist, that every declared path exists, that bundled trees carry `LICENSE` (plus `NOTICE` for Apache-2.0), that informed-by references end with exactly one attribution paragraph (`Informed by **<project>** (…) … See credits/README.md.`) and are never a `SKILL.md`, and that each informed-by upstream has a row in the by-layer table above naming `owner/repo` and the license. `--remote` adds a `git ls-remote` note when an upstream has moved past its pin; it never fails the gate.

**Linking a new upstream** follows one path: add its entry to `upstream.json` (allowlisted license, full 40-hex commit, `pinned_at` the day you read it; `pinned_version` is the version in the upstream's top-level package manifest — `package.json`, `pyproject.toml` or `.claude-plugin/plugin.json` — and `notes` names that file) → author the reference under the owning skill's `references/` in fabius's own voice, no files copied → end it with the attribution footer that names the project and this file → add its row to the by-layer table above carrying the `owner/repo` token and the license → `bash scripts/verify-all.sh --mode=dev` goes green → seal and release as usual. A bundled tree takes the same path with `consumed_as: "bundled"`, its `LICENSE` inside the tree and a changes-stated `NOTICE` when the license is Apache-2.0.
